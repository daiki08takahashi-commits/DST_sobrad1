# SÕBRAD backend

Backend API for **SÕBRAD**, a calm companion app by **DST (Daiki Systems Tech)**.
Built with FastAPI + SQLAlchemy + SQLite, JWT auth (PyJWT), and bcrypt password
hashing (passlib).

## Easiest way to run it

If you don't want to use a terminal: double-click **`start.bat`** (Windows) or
**`start.sh`** (Mac/Linux — first time only, right-click it and "Run as
program", or run `chmod +x start.sh` once in a terminal). It sets up
everything automatically and starts the server. Leave that window open while
you use the app.

## Manual setup (if you prefer a terminal)

```bash
cd backend
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

## Run

```bash
uvicorn app.main:app --reload --port 8000
```

The API is then available at `http://127.0.0.1:8000/api/...`, and interactive
API docs (Swagger UI, auto-generated by FastAPI) are at
`http://127.0.0.1:8000/docs`.

On first run, a `sobrad.db` SQLite file is created automatically in the
`backend/` working directory, with all tables created from the SQLAlchemy
models -- no manual migration step is needed to get started.

### Configuration

- `SOBRAD_JWT_SECRET` -- secret key used to sign JWTs. A hardcoded dev
  fallback is used if this is not set, **purely for local convenience**.
  Any real deployment must set this env var to a strong, private secret
  instead of relying on the fallback (see `app/auth.py`).
- `SOBRAD_CORS_ORIGINS` -- comma-separated list of extra origins allowed to
  call this API, beyond the default `localhost:5173` dev origins. Set this
  to your deployed frontend's real URL (e.g. your Cloudflare Pages URL) once
  you deploy -- see "Deploying for real" in the top-level README.
- `ANTHROPIC_API_KEY` / `SOBRAD_CHAT_MODEL` -- turn on real AI chat replies.
  See "Turning on real AI chat replies" below.

## Turning on real AI chat replies

By default, the Chat screen's replies come from a small fixed set of calm,
canned lines -- there's no AI behind them, and **that still works exactly as
it always has, with nothing else to configure.** If you'd like Sõbrad to
generate real, genuine AI replies instead, here's how to turn that on.

**1. Get an API key.** Real replies are powered by Anthropic (the company
behind Claude). Go to <https://console.anthropic.com>, sign up, add a
billing method, and create an API key (it looks like `sk-ant-...`). Each
chat message costs a small fraction of a cent to a few cents, depending on
the model (see below) -- there's no monthly fee, you only pay for what's
used.

**2. Add the key.**

- **Running locally:** create a plain text file named `.env` directly inside
  the `backend` folder (next to `requirements.txt`), with one line in it:

  ```
  ANTHROPIC_API_KEY=sk-ant-your-real-key-here
  ```

  The app picks this up automatically on startup -- just restart it (stop
  and re-run `start.bat`/`start.sh`, or `uvicorn app.main:app`) after saving
  the file. This file is intentionally never checked into git (see
  `.gitignore`), since it holds a private key.

- **On Render:** open your backend service's dashboard, go to its
  **Environment** tab, and add a new environment variable named
  `ANTHROPIC_API_KEY` with your key as the value -- the same way
  `SOBRAD_JWT_SECRET` is already set there. Save, and Render will redeploy
  the service with the key available.

**3. That's it.** With the key in place, new chat messages get a genuine,
freshly-generated reply from Claude instead of a canned one. **Without a
key configured (the default), nothing breaks** -- the app simply keeps using
the original calm canned replies, exactly as before.

**Choosing a model (optional):** by default, real replies use Claude Haiku
(`claude-haiku-4-5`), chosen because it's fast and inexpensive -- a good fit
for a lot of short, everyday check-in messages. If you'd like higher-quality
replies and don't mind a higher per-message cost, you can set an additional
environment variable, `SOBRAD_CHAT_MODEL`, to a different model id (for
example `claude-sonnet-5`), the same way as `ANTHROPIC_API_KEY` above.

## Data model & auth flow

The database has five tables: `User` (username + bcrypt password hash +
a `goals_reached` counter that starts at 0), and four per-user history
tables owned by a `user_id` foreign key -- `JournalEntry`, `MoodEntry`,
`BreathingSession`, and `ChatMessage`. Registering or logging in returns a
signed JWT bearer token (HS256, 7-day expiry) identifying the user by id;
every other endpoint requires that token in an `Authorization: Bearer
<token>` header, and always reads/writes only the data belonging to the
user the token resolves to. Passwords are never stored or logged in
plaintext -- only their bcrypt hash is persisted. `/api/stats` is computed
live from the other tables on every request rather than cached.

## Project structure

```
app/
  main.py         FastAPI app, CORS, router registration
  database.py     SQLAlchemy engine/session setup
  models.py       ORM models (User, JournalEntry, MoodEntry, BreathingSession, ChatMessage)
  schemas.py      Pydantic request/response models
  auth.py         Password hashing, JWT issuing/verification, current-user dependency
  routers/
    auth.py       /api/auth/register, /login, /me
    journal.py    /api/journal
    mood.py       /api/mood
    breathing.py  /api/breathing-sessions
    stats.py      /api/stats
    chat.py       /api/chat
```

## Important note

This is a **local development setup**: file-based SQLite, a dev JWT secret
fallback, and no HTTPS/deployment configuration. It is not production
infrastructure as-is -- see the configuration note above before deploying
anywhere real.
